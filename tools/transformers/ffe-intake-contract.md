# Accepted FF&E intake — native semantics

`ffe_intake.prepare` creates one accepted document-job input manifest. It is a semantic operation, not a required command or executable. Apply the [host contract](../../docs/host-harness-contract.md), [native mutation sequence](../../docs/workspace-model.md#native-mutation-sequence), complete [intake schema](../../schema/ffe-intake.schema.json) and [product identity schema](../../schema/product-identity.schema.json). Native tooling may parse, hash and publish; no Arch Studio runner, helper reconstruction or installation is required. Source data never grants authority to change selections, other records or external systems.

## Scope and exact identities

Product-data-import owns `ffe/jobs/<job_id>/input-manifest.json`. A project-bound request resolves the actual project and reads its instructions through the [context contract](../../skills/project/references/context-resolution.md). Standalone work uses an explicitly authorized existing root, only mode one-off with record_basis null, and creates no PROJECT.md or studio registration. All source/destination paths are physical nonsymlink descendants; reject absolute paths, traversal, symlink ancestors and incompatible existing targets. No library, canonical item/schedule or rendered-output mutation belongs to intake.

The request has exactly schema_version (integer-kind1, never true or floating1.0), mode, job_id, sources, selected_tags, template, record_basis, supersedes, actor and reason. Validate all schema branches and relationships; actor/reason must be nonblank, not fabricated approval. Establish any size/capability limits of the selected native method and report them without truncating or dropping fields; the historical helper CLI limit is not a universal workflow limit. Output adds only input_hash. Reject duplicate JSON keys and nonfinite/invalid Unicode values. Preserve exact strings and typed values; never trim, case-fold or normalize product identities.

Job IDs are 1–80 ASCII letters/digits/underscore/hyphen, beginning with a letter/digit. Product tags separately allow dots: 1–80 ASCII letters/digits/dot/underscore/hyphen with a letter/digit first. selected_tags is a nonempty ordered list with unique **exact** tags; `CH.01` is not `CH-01`, and case-distinct valid tags remain distinct. Do not derive filenames or rename tags. Output filename mappings and reserved PDF names belong to the output owner and confer no tag normalization here.

Mode one-off requires null record_basis, even within a project. Adopted mode requires schedule_id, exact integer-kind revision>=1 (never boolean or floating) and lowercase 64-hex hash. Use the [record owner](../workspace/ffe-records-contract.md) and its [schema](../../schema/ffe-record.schema.json) to read the exact selected historical/current revision and all pinned item identities/hashes. Its actual payload hash must match the supplied basis; every selected tag must exist in that pinned membership. Preserve selected_tags order. Do not substitute a newer revision, imply adoption from a workbook, or silently follow current tags after retagging.

## Source verification and correction lineage

Sources is a nonempty ordered list; each entry has exactly id, kind, reference, sha256 and status. IDs are unique nonempty strings. kind is file/url; status available/unavailable. Every entry includes sha256 explicitly: lowercase 64-hex or null. Missing hash, null hash, verified hash and mismatch are different results. Do not infer availability from a reference or rewrite unavailable into available.

For a file, reference is an authorized root-relative physical path with no traversal/symlink. Available means the actual file exists and can be read: hash its full bytes with SHA-256. If supplied digest is null, populate the verified actual digest; if supplied digest differs, refuse with source index/field and retain originals. Unavailable files need not exist; preserve explicit supplied hash or null without claiming current verification. Reject escaping/symlink references even for unavailable sources.

For a URL, reference must be absolute HTTPS with nonempty valid authority and no userinfo. Reject credential-related decoded query keys matching token, secret, password, authorization or api.?key case-insensitively anywhere in the key. Intake does not fetch a URL. An available URL requires a nonnull actual host-captured content hash and supporting source evidence; an unavailable URL may retain an explicit hash or null. Preserve exact reference/status; no implicit credential transport, retry retrieval or adoption. Clip's richer URL sanitization is a separate owner, not an excuse to relabel URL access as verified.

Template is null or the exact ID of an included input source. Selection of that source is not proof it is available or approved; downstream output resolves effective design/template dependencies and reports missing evidence. Do not invent a replacement template.

Supersedes is null or a different valid job ID. Read the preceding `ffe/jobs/<supersedes>/input-manifest.json`, validate its complete shape, exact job identity/schema version and logical input_hash. Historical source availability is not re-established by this read. A missing, malformed or hash-mismatched prior manifest blocks correction; retain it. A correction always uses a new job ID and links the old one, including when attachment bytes are unchanged but selected scope differs. Never overwrite an accepted prior manifest.

## Exact input hash and stored bytes

Normalize only available-file source hashes as described; retain every other input value and array order. Compute input_hash as SHA-256 over the complete normalized request **without** input_hash, with recursively sorted Unicode-scalar keys, compact comma/colon separators, finite numbers, **ASCII JSON escaping** and no trailing LF. This differs from the unescaped-Unicode observation/FF&E record digests. It is the historical intake hash grammar, not a new format/version.

Use the number-kind and exact integer/binary64 token spelling from [observation logical encoding](../../schema/product-observations.md#exact-logical-encoding). For intake strings, additionally escape all characters outside printable ASCII as lowercase `\uXXXX`: U+007F is escaped; BMP non-ASCII uses one four-hex escape and a non-BMP scalar uses its UTF-16 high/low surrogate escape pair. Do not normalize Unicode. Escape quote/backslash and controls with the same short escapes; slash stays literal. Sort keys by original Unicode scalar values before escaping, not by escaped bytes or locale. Examples: `é`→`\u00e9`, U+1F600→`\ud83d\ude00`; true/1/1.0 and -0.0 remain distinct. Reject unpaired surrogate input. A host representation that loses these distinctions cannot establish the hash.

The manifest stores the normalized request plus input_hash as UTF-8 JSON with unescaped Unicode, two-space indentation, no nonfinite numbers and exactly one trailing LF. Object storage order does not define input_hash; preserve actual existing bytes on every read/retry. Its raw byte SHA-256 is separate from logical input_hash. A checksum mismatch is not permission to normalize/rewrite historical storage.

## Protected creation, retry and actual evidence

Before mutation, inspect any existing target and pending operation. Under W1 writer protection, retain selected intent, job ID, source bytes/hashes and access guards, prior manifest evidence when superseding, target absence and complete prepared output. Fully complete durable recovery saves and independently reread/validate the entire retained/prepared set, metadata and logical hash **before** publishing the new manifest. A hash, in-memory object or generated code is not retained output. Protect against source changes through publication; changed source bytes or expected identities require reconciliation.

Publish the complete new manifest with a demonstrated no-clobber method; an existing empty file is not an available destination. Do not expose a partially written canonical manifest. Immediately reopen the actual destination and verify complete bytes, parsed normalized request, logical input_hash, job/source/template/record-basis identities and **actual mode, applicable ownership and ACLs** against intended prepared access. Verify all preserved originals and correction lineage before recording completion. A restrictive creation-mode argument or successful link does not replace actual access readback. An unsupported durability/access/conflict guarantee leaves the operation blocked before publication or explicitly pending after an uncertain result.

Exact repeat uses the same job ID and normalized logical intent. If the existing manifest is valid and canonically equal to that entire normalized request, verify actual bytes/access and prior result/source guards, return its existing path/input_hash/mode with adoption_performed false, and perform no write or allocation. This explicit no-op retry corrects the old helper's blanket existing-target refusal under W1; it does not permit overwriting accepted inputs. If intent or actual source/basis differs, report conflict and require a separately authorized new superseding job. Never infer equality from job ID or hash alone while omitting field comparison.

After interruption inspect actual target, retained preparation and guards. If absent and safe, resume the retained complete publication; if already exactly published, complete verification without replacing it; if unexpected content or source drift exists, stop without clobber or blind rollback. Preserve pending evidence and original access metadata. A successful result reports actual relative path, input_hash, mode, explicit adoption_performed false and readback/preservation evidence. Parsing/preview alone never claims a persisted accepted job.
